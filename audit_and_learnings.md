# Project Zara: End-to-End Audit & Pipeline Learnings

This document outlines the current state of the Project Zara pipeline, auditing why recent end-to-end runs failed to produce output, analyzing the root causes behind generic drafts, and detailing the fixes implemented to optimize the system.

---

## 1. Why We Aren't Getting Output Right Now (API Exhaustion)

The pipeline currently relies on three separate LLM providers (Groq, Gemini, Z.ai). Extensive testing and the initially inefficient token usage (processing up to 30+ scraped articles per prospect simultaneously) caused us to hit absolute hard limits across the board:

*   **Groq:** Exhausted the organization's **500,000 Tokens Per Day (TPD)** limit.
*   **Gemini:** Exhausted the Free Tier's **1,500 Requests Per Day (RPD)** limit (even with our 30-second backoff loop to manage the 15 RPM limit).
*   **Z.ai:** The API is currently hanging/unresponsive, triggering 60-second `ReadTimeout` exceptions during inference.

**Conclusion:** The pipeline logic is sound and the bugs are fixed, but the end-to-end script cannot execute successfully until the API rate limits reset at midnight (or a higher-tier API key is provided).

---

## 2. Deep Audit of the Last Successful E2E Run

Before the API limits were completely exhausted, the pipeline successfully executed an end-to-end run for **Glen Braganza at Versapay**. 

### The Data Scrape
The web scrapers worked flawlessly, retrieving a total of **27 data cards**:
*   Tavily: 12 cards
*   Google News: 6 cards
*   Exa (News, YouTube, Edgar, LinkedIn): 8 cards
*   Jina: 1 card

### The Ranker's Conclusion
Despite processing 27 pieces of information, the Ranker outputted the following:
```text
=== RANKING LOG ===
Claim Strength: no_signal
ICP Fit: unknown
ICP Notes: ['headcount unknown — could not verify']

=== HOOKS ARTICULATED ===
  (No hooks generated by Ranker)
```

### Why Was the Output Generic?
The Ranker was acting as a "dumb LLM" governed by overly strict instructions. It was told to *only* extract hooks that mapped directly to specific "Pain Points" defined in the Value Proposition. 
Because the 27 articles contained general company news and executive updates rather than explicit complaints about pain points, the Ranker ruthlessly discarded **all 27 cards**. 

Since 0 hooks were generated, the Drafter had no ammunition and was forced to output a generic, template-based fallback email.

## 3. Implemented Fixes & Architectural Upgrades

To resolve both the API token burn and the overly strict filtering, the following upgrades have been implemented in `zara/ranker.py` and `zara/drafter.py`:

### A. Smart Token Optimization (Lazy Evaluation)
We moved away from the "dump everything into the LLM" approach. 
1.  **Pre-Sorting:** Before talking to the LLM, the system now mathematically sorts all scraped cards by **Proximity** (`authored` > `attributed` > `company_action`) and **Recency** (newest first).
2.  **Hard Capping:** The Ranker now enforces a strict maximum of **15 cards**. The long tail of irrelevant search results is instantly discarded.
3.  **Early Exit:** The top 15 cards are processed by the LLM in small batches of 5. If the LLM finds a "Strong Hook" (Score >= 0.8) in the first batch, it **instantly stops processing** the remaining cards.
    *   *Result:* This saves up to 80% of API token costs per prospect and prevents daily limits from being exhausted prematurely.

### B. "Weak Hooks" (Relaxed Strictness)
We loosened the Ranker so it no longer throws away valuable context.
1.  **Fallback Category:** A new `general_news` category was injected into the prompt.
2.  **Weak Signal Recognition:** The Ranker is now instructed: *"If a snippet contains interesting company/person news but does not map to a specific pain point, map it to `general_news` with a score of 0.4."*
3.  **Drafter Integration:** The Drafter was updated to recognize `general_news` hooks. Instead of generating a generic fallback email, it uses the weak hook as a personalized icebreaker (e.g., *"We don't know their specific pain yet, but saw the news about X and wanted to start a conversation..."*).
